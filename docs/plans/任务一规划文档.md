# 任务一规划文档：Monte Carlo 模拟数据生成

## 一、任务目标与边界

- 任务一负责设计并实现 3 个数据生成过程（DGP），并对**每个场景独立运行 500 次 Monte Carlo 循环**。
- 任务一的重点是：数据生成、结果保存、基础自检、保证可复现。
- 任务一的输出将直接供任务二使用。
- 任务一**不在本文档中写死**任务二的匹配实现细节，包括但不限于：匹配算法、卡尺、邻居数、是否放回、共同支持裁剪规则。

---

## 二、统一设定

### 2.0 统一主题与现实背景

**统一研究主题**：更严格的环境监管政策对企业绿色投资的影响

**统一现实故事**：某地区在第 4 年初实施了更严格的环境监管政策，将部分企业纳入重点监管名单。研究者希望使用企业面板数据，评估这一政策对企业绿色技术投资额的因果影响。

任务一中的三个场景共用这一研究主题，但通过不同的数据生成机制，分别模拟：

- DID 在理想条件下有效的基准世界
- PSM-DID 能修正可观测趋势差异的世界
- 即使使用 PSM-DID 也会因为不可观测时间变化混淆而失败的世界

这样设计的目的，是让后续任务二、任务三中的结果解释始终围绕同一个现实问题展开，而不是变成三个彼此割裂的抽象统计练习。

### 2.1 面板结构与 Monte Carlo 规模

| 项目 | 设定 |
|:---|:---|
| 个体数 | 1000 家企业 |
| 时期数 | 6 年，`t = 1, 2, 3, 4, 5, 6` |
| 政策开始时点 | 第 4 年初 |
| 每个场景的重复次数 | 500 次 |
| 目标处理组规模 | 约 30%，即约 300 家企业 |

### 2.2 统一符号与参数

定义：

- `post_t = 1(t >= 4)`：处理后时期指示变量
- `s_t = t - 1`：线性时间刻度，用于表示趋势斜率差异
- `τ = 50`：真实处理效应（万元）
- `λ_t = 5 * s_t`：共同时间趋势

随机项与协变量：

- `X_i ~ N(0, 1)`：处理前可观测协变量，表示企业初始规模
- `U_i ~ N(0, 1)`：不可观测协变量，仅场景 C 使用，表示 CEO 环保倾向
- `η_i ~ N(0, 15^2)`：企业层随机扰动
- `ε_it ~ N(0, 10^2)`：个体-年份扰动

个体固定效应：

- 场景 A、B：`α_i = 100 + 10X_i + η_i`
- 场景 C：`α_i = 100 + 10X_i + 5U_i + η_i`

处理前潜在结果与观测结果：

- `Y_it(0) = α_i + λ_t + κ_i * s_t + ε_it`
- `Y_it = Y_it(0) + D_i * τ * post_t`

其中 `κ_i` 是场景相关的趋势驱动项：

- 场景 A：`κ_i = 0`
- 场景 B：`κ_i = 4X_i`
- 场景 C：`κ_i = 4U_i`

说明：

- 这样写的目的是让场景 B、C 的处理组和控制组在时间上表现出**斜率差异**，而不是只在处理后出现一次性水平跳跃。
- 处理效应只在 `post_t = 1` 时生效，避免把政策效应错误地施加到处理前时期。
- 在当前设定下，场景 B 和场景 C 的趋势异质性从处理前时期就已经存在，这一点是有意保留的：未匹配样本的组均值路径会在处理前就表现出非平行趋势。
- 场景 B 的关键点不是“处理前绝对平行”，而是“给定 `X_i` 后，未处理潜在趋势的系统差异完全由 `X_i` 刻画”；因此若任务二后续在 `X_i` 上成功匹配，可恢复条件可比性。
- 场景 C 则对应“给定观测到的 `X_i` 后仍不可比”，因为真正驱动趋势斜率的是不可观测变量 `U_i`，所以匹配无法修复该偏误。

## 三、三个场景的 DGP

### 场景 A：DID 的基准世界

现实对应：

- 环保部门采用接近随机抽签的方式，从样本企业中抽取约 30% 进入重点监管名单。
- 企业是否进入处理组，与其规模、治理特征、环保偏好等因素都无系统关系。
- 因此在政策发生前后，处理组和控制组除了是否被纳入监管外，并不存在结构性差异。

处理分配：

- `D_i ~ Bernoulli(0.30)`

结果生成：

- `κ_i = 0`
- `Y_it(0) = α_i + λ_t + ε_it`
- `Y_it = Y_it(0) + D_i * τ * post_t`

识别意图：

- 处理组和控制组的差异来自随机分配。
- 差异不是系统性的，既不依赖可观测变量，也不依赖不可观测变量。
- 不存在组别特有的时间趋势差异。
- 这是 DID 应表现良好的基准场景。

场景说明：

- **处理组与控制组为何不同**：两组的形成完全来自随机抽样，差异只来自有限样本波动，而不是系统性选择。
- **差异是可观测还是不可观测**：不存在稳定的系统差异；若有均值差，也只是随机误差造成的暂时偏离。
- **差异是否随时间变化**：不会。两组共享相同的共同时间趋势 `λ_t`，不存在组别特有的趋势项。
- **预期哪种方法更有效，哪种方法可能失效**：`DID` 应最稳健；`PSM-DID` 理论上也能给出接近真实值的结果，但通常不会优于 DID；单独 `PSM` 因不利用前后差分，可能受水平差异和噪声影响而较不稳定。

### 场景 B：可观测趋势异质性

现实对应：

- 环保部门采取“抓大放小”的监管策略，更倾向于把初始规模较大的企业纳入重点监管名单。
- 同时，大企业通常拥有更强的融资能力、设备更新能力和绿色转型基础，因此即使没有政策，它们的绿色投资增长速度也往往更快。
- 这意味着处理组和控制组的差异主要来自一个**可观测**因素：企业初始规模。

处理分配：

- `P(D_i = 1 | X_i) = logit^{-1}(-0.95 + 0.8X_i)`

结果生成：

- `κ_i = 4X_i`
- `Y_it(0) = α_i + λ_t + 4X_i * s_t + ε_it`
- `Y_it = Y_it(0) + D_i * τ * post_t`

识别意图：

- 处理组和控制组的差异来自可观测变量 `X_i`。
- 企业规模越大，越容易进入处理组，且其自然增长趋势也越快。
- 差异会随时间累积，因此未匹配 DID 会混入由 `X_i` 驱动的趋势偏误。
- 若任务二后续在 `X_i` 上成功匹配，条件平行趋势应可恢复。

场景说明：

- **处理组与控制组为何不同**：大企业更容易进入处理组，而企业规模 `X_i` 同时决定绿色投资的自然增长斜率。
- **差异是可观测还是不可观测**：是可观测差异，因为驱动分配和趋势异质性的核心变量是 `X_i`，任务二理论上可以看到并用于匹配。
- **差异是否随时间变化**：会。由于 `4X_i * s_t` 的存在，`X_i` 越大的企业，其未处理潜在结果 `Y_it(0)` 增长越快，组间差异随时间累积扩大。
- **预期哪种方法更有效，哪种方法可能失效**：未匹配 `DID` 预期会偏误，因为会把由 `X_i` 驱动的趋势差异误记为处理效应；`PSM-DID` 若在 `X_i` 上成功恢复可比性，应优于朴素 DID；单独 `PSM` 即便能平衡水平差异，也无法自然消除时间维度上的趋势偏误，因此仍可能失效。

### 场景 C：不可观测的时间变化混淆

现实对应：

- 环保部门表面上参考企业规模和公开指标，但真正影响企业是否更容易被纳入重点监管名单的，还包括管理层的环保偏好、战略主动性、对绿色转型的重视程度等隐含因素。
- 这些隐含因素无法在样本数据中直接观测，但它们不仅影响企业是否进入处理组，还影响企业在没有政策时的绿色投资增长速度。
- 因此，处理组和控制组的关键差异并不完全体现在可观测变量上，而是部分隐藏在不可观测因素中。

处理分配：

- `P(D_i = 1 | X_i, U_i) = logit^{-1}(-0.95 + 0.2X_i + 0.8U_i)`

结果生成：

- `κ_i = 4U_i`
- `Y_it(0) = α_i + λ_t + 4U_i * s_t + ε_it`
- `Y_it = Y_it(0) + D_i * τ * post_t`

识别意图：

- 处理组和控制组的关键差异来自不可观测变量 `U_i`。
- `U_i` 同时影响进入处理组的概率和自然增长斜率。
- 即使任务二只在 `X_i` 上做匹配，也无法消除 `U_i` 驱动的趋势差异。
- 这是 PSM-DID 也可能失败的场景。

场景说明：

- **处理组与控制组为何不同**：进入处理组的关键驱动力不是观测到的企业规模，而是不可观测的 `U_i`；同时 `U_i` 还决定未处理潜在结果的增长速度。
- **差异是可观测还是不可观测**：是不可观测差异。`U_i` 在数据生成阶段存在，但正式交付数据中不会保留。
- **差异是否随时间变化**：会。由于 `4U_i * s_t` 的存在，`U_i` 会持续影响 `Y_it(0)` 的斜率，导致组间差异随时间扩大。
- **预期哪种方法更有效，哪种方法可能失效**：未匹配 `DID` 会偏误；`PSM-DID` 即使在 `X_i` 上匹配成功，也无法消除 `U_i` 导致的时间变化混淆，因此仍可能失败；单独 `PSM` 则更容易同时受到水平差异与趋势差异影响。

## 四、任务一执行步骤

1. 固定统一参数，定义 3 个场景的 DGP。
2. 对每个场景分别运行 `sim_id = 1, ..., 500`。
3. 每次循环生成一个 `1000 x 6` 的企业面板。
4. 保存字段：`scenario`、`sim_id`、`firm_id`、`year`、`post`、`D`、`Y`、`X`。
5. 场景 C 在正式输出时删除 `U_i`，不写入交付数据。
6. 生成基础自检结果，至少包括：
   - 各场景处理组占比统计
   - 各场景基于 `Y(0)` 的组均值趋势图或等价摘要
   - 场景 B、C 基于真值处理概率的分布对比图或等价摘要，用于检查共同支持是否严重缺失
   - 随机种子与复现说明

其中：

- `Y(0)` 相关图表仅用于任务一内部真值自检，不属于正式交付数据字段。
- 为完成真值检查，调试阶段允许临时生成包含 `Y_it(0)`、`Y_it(1)` 的内部版本数据，但正式交付版本必须删除这些字段。

建议的随机种子策略：

- 场景 A：`seed = 1000 + sim_id`
- 场景 B：`seed = 2000 + sim_id`
- 场景 C：`seed = 3000 + sim_id`

实现建议：

- 每次 `sim_id` 循环内部创建独立随机数生成器，例如 `rng = np.random.default_rng(seed)`。
- 不依赖全局随机状态连续推进，避免不同场景或前序循环对后续结果产生隐含影响。

## 五、任务一输出物

- `任务一规划文档.md`：本文档
- `任务一_模拟设计.py`：生成 3 个场景、各 500 次循环的主脚本
- 模拟数据文件：建议按场景分别保存为 Parquet 文件
- `任务一_自检结果.md` 或对应图表文件：记录处理率、趋势自检和复现信息

正式输出数据中应包含以下字段：

- `scenario`
- `sim_id`
- `firm_id`
- `year`
- `post`

- `Y`
- `X`

正式输出数据中**不应包含**：

- `U_i`
- `Y_it(0)`

- 调试阶段允许保留包含 `U_i`、`Y_it(0)`、`Y_it(1)` 的临时内部版本，用于核对场景设定、趋势路径和真值。
- 正式交付给任务二或用于最终提交的版本，必须删除这些字段。

## 六、核心约束

1. 三个场景都必须各自完成 500 次 Monte Carlo 循环，不能只生成单次样本。
2. 三个场景的真实处理效应统一固定为 `τ = 50`，不在后续流程中改动。
3. 三个场景的目标处理组规模统一为约 30%，即约 300 家企业；允许单次模拟存在随机波动，但 500 次平均占比应稳定在 30% 附近。
4. 场景 B 和场景 C 必须体现**趋势斜率差异**，不能退化成仅在处理后发生一次性跳跃。
5. 政策效应只能在 `t >= 4` 时进入观测结果，不能污染处理前时期。
6. 调试阶段允许临时保留 `U_i`、`Y_it(0)`、`Y_it(1)` 等真值或隐藏字段做自检，但正式交付数据必须删除。
7. 任务一只负责生成可供任务二使用的数据，不提前规定任务二的匹配实现细节。

## 七、验收标准

- 已清楚写出场景 A、B、C 的 DGP，且三者的差异来源明确。
- 每个场景都完成 500 次循环，总数据可复现。
- 每个场景的单次模拟规模为 `1000 x 6`，并带有 `sim_id`。
- 按场景统计，在 500 次模拟上的平均处理组占比落在 `0.28` 到 `0.32` 之间。
- 场景 A 的 `Y(0)` 组均值路径基本平行。
- 场景 B 的 `Y(0)` 组均值差异由 `X_i` 驱动，并随时间累积。
- 场景 C 的 `Y(0)` 组均值差异由不可观测的 `U_i` 驱动，并随时间累积。
- 重新运行同一脚本、同一随机种子时，输出结果一致。
- 正式交付数据不包含 `U_i`、`Y_it(0)`、`Y_it(1)` 等仅用于调试或真值检查的字段。
