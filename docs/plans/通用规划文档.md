# 通用规划文档：用 Monte Carlo 模拟理解 PSM-DID

## 一、文档定位

本文档用于描述**整个项目**的通用规划，而不是只服务于某一个子任务。

它回答 4 个核心问题：

1. 项目整体要完成什么。
2. 项目中的代码、数据、图表、文档应该怎么组织。
3. 每个阶段分别要做什么、产出什么。
4. 整个项目必须共同遵守哪些约束。

---

## 二、项目总体目标

本项目围绕课程作业《用 Monte Carlo 模拟理解 PSM-DID》展开，总体目标是完成以下 4 类工作：

1. 设计 3 个以上有明确识别含义的数据生成过程（DGP）。
2. 在每个场景下比较 `PSM`、`DID`、`PSM-DID` 的估计表现。
3. 基于模拟结果解释不同方法为什么有效或失效。
4. 评价 1 篇真实使用 `PSM-DID` 的经济学论文。

最终交付应是一套**可复现的仓库**，其中包含：

- 研究报告
- 模拟与估计代码
- 结果图表与汇总表
- 论文评价材料
- AI 使用记录

### 3.1 代码放置原则

- `src/simulation/`：放任务一相关代码，即 DGP、场景定义、Monte Carlo 循环、数据自检。
- `src/estimation/`：放任务二相关代码，即 `PSM`、`DID`、`PSM-DID` 的实现。
- `src/analysis/`：放指标计算、汇总表输出、图表生成。
- `src/utils/`：放读写、路径管理、随机种子管理等通用工具。
- `scripts/`：放可直接运行的入口脚本，负责串联 `src/` 中的模块。

### 3.2 数据放置原则

- `data/raw/`：保存任务一直接生成的模拟原始面板数据。
- `data/interim/`：保存任务二中间结果，例如每次模拟的估计值、匹配后样本信息。
- `data/processed/`：保存已整理好的汇总结果，供报告直接引用。
- `data/external/`：保存外部资料，例如论文 PDF、参考资料等。

### 3.3 输出文件放置原则

- `outputs/figures/`：趋势图、分布图、共同支持图、平衡性图等。
- `outputs/tables/`：方法比较汇总表、场景结果表、论文评价结构表等。
- `outputs/checks/`：任务一和任务二的自检结果。
- `outputs/logs/`：运行日志、参数快照、异常信息。

### 3.4 文档放置原则

- 根目录或 `docs/`：规划、提纲、阶段性说明文档。
- `reports/`：最终要提交或汇总进最终成果的正式文本。

## 四、核心技术栈

项目建议统一采用 `Python` 实现，技术栈如下：

| 工具 / 库 | 用途 |
|:---|:---|
| `Python 3.10+` | 项目主语言 |
| `numpy` | 随机数生成、向量化计算、Monte Carlo 循环 |
| `pandas` | 面板数据整理、结果汇总、文件读写 |
| `statsmodels` | DID 回归、Logit / Probit、统计建模 |
| `scikit-learn` | 倾向得分建模、最近邻匹配的辅助实现 |
| `matplotlib` | 基础图表输出 |
| `seaborn` | 统计图可视化 |
| `pyarrow` | Parquet 文件读写 |
| `Jupyter Notebook` | 调试、探索性分析，可选 |
| `Markdown` | 研究报告、规划文档、AI 使用记录 |
| `Git / GitHub / Gitee` | 版本管理与作业提交 |

技术栈使用原则：

- 任务一到任务四尽量共用同一套环境，避免不同阶段切换工具链。
- 正式交付以 `.py + .md + figures/tables` 为主，不依赖 Notebook 才能复现。
- 若使用 Notebook，只作为中间探索工具，不作为唯一交付代码。

## 五、项目总体任务与具体分解

### 5.1 总体任务图

项目按逻辑顺序分为 5 个阶段：

1. 项目脚手架与环境统一
2. 任务一：DGP 设计与 Monte Carlo 数据生成
3. 任务二：方法实现与结果比较
4. 任务三与任务四：理论解释与论文评价
5. 研究报告整合与最终提交

### 5.2 阶段一：项目脚手架与环境统一

目标：

- 建立一致的目录结构、路径约定和运行入口。

具体事项：

- 确定代码目录、数据目录、输出目录。
- 准备 `requirements.txt`。
- 确定统一随机种子管理方式。
- 确定命名规范，例如场景名、数据文件名、图表文件名。

输出物：

- 项目目录结构
- `requirements.txt`
- `README.md` 或运行说明

### 5.3 阶段二：任务一

目标：

- 设计并实现 3 个场景的 DGP。
- 每个场景完成 500 次 Monte Carlo 循环。
- 输出可供任务二直接使用的模拟数据。

具体事项：

- 明确场景 A、B、C 的识别逻辑。
- 统一样本量、时期数、真实处理效应、处理组比例口径。
- 编写 DGP 生成函数与循环运行脚本。
- 生成基础自检结果，验证趋势和处理分配符合设计预期。

输出物：

- `任务一规划文档.md`
- `src/simulation/` 下的实现代码
- `scripts/run_task1_generate.py`
- `data/raw/` 下的原始模拟数据
- `outputs/checks/` 下的自检结果

### 5.4 阶段三：任务二

目标：

- 在每个场景下比较 `单独 PSM`、`单独 DID`、`PSM-DID`。

具体事项：

- 从任务一读取模拟数据。
- 实现 3 类方法。
- 保存每次模拟的估计值。
- 汇总平均估计值、`Bias`、`RMSE`、标准差。
- 输出关键图表，例如估计值分布图、平衡性图、共同支持图。

输出物：

- `src/estimation/` 下的方法实现代码
- `scripts/run_task2_estimate.py`
- `data/interim/` 下的单次估计结果
- `data/processed/` 下的汇总结果
- `outputs/figures/`、`outputs/tables/` 下的可视化与表格

### 5.5 阶段四：任务三

目标：

- 基于模拟结果解释不同方法在不同场景下为何有效或失效。

具体事项：

- 将场景 A、B、C 的结果与方法假设一一对应。
- 解释可观测选择、不可观测异质性、条件平行趋势、共同支持等问题。
- 明确 `ATE` 与 `ATT` 的区别，并结合本项目场景说明。

输出物：

- 理论解释提纲或正文文档
- 可直接写入研究报告的文字稿

### 5.6 阶段五：任务四

目标：

- 评价 1 篇真实使用 `PSM-DID` 的论文。

具体事项：

- 选题并收集论文信息。
- 审阅研究问题、处理变量、匹配变量、平行趋势检验、共同支持检验。
- 结合本项目模拟经验评价其识别可信度与脆弱点。

输出物：

- `reports/论文评价.md` 或等价文档
- 论文引用信息与材料归档

### 5.7 阶段六：报告整合与提交

目标：

- 将任务一到任务四的结果整合为一份完整、规范、可复现的课程作业仓库。

具体事项：

- 汇总图表与表格。
- 整理研究报告。
- 整理 AI 使用记录。
- 检查代码、数据、文档之间引用是否一致。

输出物：

- `reports/研究报告.md`
- `reports/AI使用记录.md`
- 最终提交仓库

## 六、项目总体核心约束

### 6.1 复现性约束

1. 所有核心结果必须可以通过脚本重新生成。
2. 随机种子必须可追踪、可复用。
3. 参数设定不能只留在文档里，代码中也必须显式定义。

### 6.2 任务边界约束

1. 任务一负责数据生成，不提前把任务二的具体匹配细节写死。
2. 任务二负责估计与比较，不替代任务三的理论解释。
3. 任务三和任务四最终都要回流到研究报告，但各自保持独立逻辑。

### 6.3 识别设计约束

1. 场景 A 必须体现 DID 的基准情形。
2. 场景 B 必须体现由**可观测变量**驱动的趋势异质性。
3. 场景 C 必须体现由**不可观测变量**驱动的时间变化混淆。
4. 三个场景的差异必须来自清晰、可解释的 DGP，而不是随意调参。

### 6.4 横向可比性约束

1. 场景之间应尽量共享统一样本量、时期数和处理效应口径。
2. 处理组规模应保持在相近水平，便于横向比较。
3. 汇总指标口径必须统一，例如都使用平均估计值、`Bias`、`RMSE`、标准差。

### 6.5 数据治理约束

1. 原始模拟数据、中间估计结果、最终汇总结果必须分层保存。
2. 不同阶段的输出文件不能混放。
3. 仅用于调试或真值检查的变量，不应无区分地进入正式交付数据。

### 6.6 学术诚信约束

1. AI 仅作为辅助工具，最终判断与结论由人负责。
2. AI 使用过程必须保留完整记录。
3. 论文、教材、网页或代码片段如被引用，必须标注来源。

## 八、当前执行建议

在当前阶段，建议按下面顺序推进：

1. 先把任务一文档与任务一代码落地。
2. 同步建立 `src/`、`scripts/`、`data/`、`outputs/`、`reports/` 基础目录。
